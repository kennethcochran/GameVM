# index-based-ast Specification

## Purpose
The AST stage uses a Struct-of-Arrays `InstList` representation where all node references are 32-bit offsets into the slab (parallel arrays). Node typing uses `AstNodeKind` in the `Tags` array, not class polymorphism or a bit-packed metadata header.

## Requirements
### Requirement: Offset-based references
All AST nodes generated by the `Pascal` and `CSharp` frontends MUST reference child nodes and sibling nodes using 32-bit offsets within the slab (`InstIndex` handles or `StringPool` offsets), rather than object references.

#### Scenario: Building a binary expression
- **WHEN** a parser processes an addition operation (`A + B`)
- **THEN** it stores the offset of `A` and `B` inside the `BinaryOp` node block in the AST slab via `FixedOps`/`Extra` arrays.

### Requirement: Enum-based Node Typing
AST Nodes MUST use an enum discriminator (`AstNodeKind`) encoded in the `Tags` array (parallel array at same index) to denote their type rather than relying on class polymorphism and `is`/`as` operators.

#### Scenario: Dispatching based on node type
- **WHEN** an evaluator or code generator processes a node
- **THEN** it reads `Tags[i]` to get `AstNodeKind` and switches on it instead of relying on virtual `Accept(Visitor)` dispatch.
